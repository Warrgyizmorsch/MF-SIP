# Mobile App Push Notification Integration & Migration Guide

## 1. Executive Summary

During push notification testing on the live backend, push delivery to connected mobile devices failed with the following Google Firebase error:

```json
{
  "code": 403,
  "message": "SenderId mismatch",
  "status": "PERMISSION_DENIED",
  "details": [
    {
      "@type": "type.googleapis.com/google.firebase.fcm.v1.FcmError",
      "errorCode": "SENDER_ID_MISMATCH"
    }
  ]
}
```

### Cause of the Issue
- The **backend service account** has been updated to use the Firebase project **`mossierp`** (`mossierp-firebase-adminsdk-fbsvc-2c9970ab81.json`).
- The **currently installed mobile app build** was compiled using configuration files from the older Firebase project **`mfsip-3aa54`**.
- In Firebase Cloud Messaging (FCM), device registration tokens are cryptographically tied to the project Sender ID specified at compile time. Sending a notification from `mossierp` to a token generated by `mfsip-3aa54` is rejected by Google with `SENDER_ID_MISMATCH`.

---

## 2. Action Required in the Mobile App (Flutter / Android / iOS)

If the team is migrating to the **`mossierp`** Firebase project, complete the following steps:

### Step 1: Download Configuration Files from Firebase Console (`mossierp`)
1. Log in to [Firebase Console](https://console.firebase.google.com/).
2. Select the project **`mossierp`**.
3. Go to **Project Settings** (Gear icon ⚙️) > **General**.
4. In the **Your apps** section:
   - For **Android**: Download `google-services.json`.
   - For **iOS**: Download `GoogleService-Info.plist`.

### Step 2: Replace Files in the Mobile Project
- **Android**:
  - Replace the file at: `android/app/google-services.json`
  - Ensure the `package_name` inside `google-services.json` matches your `applicationId` in `android/app/build.gradle`.
- **iOS**:
  - Replace `ios/Runner/GoogleService-Info.plist` via Xcode to ensure file reference integrity.
  - Verify that the `BUNDLE_ID` in `GoogleService-Info.plist` matches your Xcode Bundle Identifier.

### Step 3: Rebuild and Install the Application
- Clean previous build artifacts:
  ```bash
  flutter clean
  flutter pub get
  ```
- Build a new release/debug APK or bundle:
  ```bash
  flutter build apk --release
  ```
- Install the newly compiled app on the test device.

## 3. FCM Device Token Sync with Backend

When the newly installed app launches or the user logs in, the app receives a new FCM token linked to the `mossierp` project. This token must be synced with the backend.

### Endpoint Details
- **Method**: `POST`
- **URL**: `https://sip-backend.londonstreetstore.com/api/v1/device-token`
- **Headers**:
  ```http
  Authorization: Bearer <USER_SANCTUM_AUTH_TOKEN>
  Accept: application/json
  Content-Type: application/json
  ```
- **Request Body**:
  ```json
  {
    "fcm_token": "<FCM_REGISTRATION_TOKEN_FROM_FIREBASE>"
  }
  ```

### Response
```json
{
  "status": true,
  "message": "Device token updated successfully."
}
```

### Alternative: During Login / OTP Verification
The `fcm_token` can also be sent directly in authentication API requests:
- `POST /api/v1/login`
- `POST /api/v1/verify-otp`
- `POST /api/v1/social-auth`

Parameter:
```json
{
  "fcm_token": "<FCM_REGISTRATION_TOKEN>"
}
```

## 4. Push Notification Payload Handling in App

The backend sends notifications formatted for Flutter/Android background and foreground handling:

### Sample Payload Sent by Backend
```json
{
  "message": {
    "token": "<DEVICE_TOKEN>",
    "notification": {
      "title": "Order Placed Successfully",
      "body": "Your SIP order of ₹5,000 for Nippon India Small Cap Fund has been submitted."
    },
    "data": {
      "type": "order_status",
      "order_id": "1042",
      "click_action": "FLUTTER_NOTIFICATION_CLICK",
      "timestamp": "1728555600"
    },
    "android": {
      "priority": "HIGH"
    }
  }
}
```

### Mobile App Code Checklist
1. **Firebase Messaging Background Handler**:
   Ensure `@pragma('vm:entry-point')` is added above `_firebaseMessagingBackgroundHandler` in Flutter.
2. **Notification Channels (Android 8.0+)**:
   Ensure a high-importance notification channel is registered:
   ```dart
   const AndroidNotificationChannel channel = AndroidNotificationChannel(
     'high_importance_channel',
     'High Importance Notifications',
     description: 'This channel is used for important transaction and account alerts.',
     importance: Importance.high,
   );
   ```
3. **Foreground Notification Presentation**:
   Configure foreground presentation options:
   ```dart
   await FirebaseMessaging.instance.setForegroundNotificationPresentationOptions(
     alert: true,
     badge: true,
     sound: true,
   );
   ```
4. **Token Refresh Listener**:
   Listen to `FirebaseMessaging.instance.onTokenRefresh` and call `POST /api/v1/device-token` whenever the token refreshes.

## 5. Alternative Solution (Zero Mobile App Rebuild)

If updating and redistributing the mobile application is not preferred right now:
1. Keep the mobile application as is (using project `mfsip-3aa54`).
2. Go to [Firebase Console - mfsip-3aa54 Service Accounts](https://console.firebase.google.com/project/mfsip-3aa54/settings/serviceaccounts/adminsdk).
3. Click **"Generate new private key"**.
4. Deploy the generated JSON file to `storage/app/firebase-service-account.json` on the backend server.
5. All existing mobile app installs will immediately receive push notifications without needing an app update.
